## Canonical terms and hash

Both contracts use `ProtocolTypes.Terms` in this exact order:

```solidity
struct Terms {
    bytes32 transactionId;
    address buyer;
    address seller;
    uint256 paymentChainId;
    address paymentContract;
    address paymentInputToken;
    uint256 paymentInputAmount;
    address paymentToken;
    uint256 paymentAmount;
    uint256 amountOutMin;
    uint256 assetChainId;
    address assetSettlement;
    address assetToken;
    uint256 assetAmount;
    uint256 expiresAt;
    uint32 schemaVersion;
}
```

`ProtocolTypes.hashTerms` hashes `abi.encode(TERMS_TYPEHASH, ...terms fields in the order above)`. The frontend `hashTerms` follows this encoding. Both local contract environments test that `DecisionPaymentSettlement.computeTermsHash` and `AssetSettlement.computeTermsHash` return the same value. The current payment contract permits direct-token settlement only: `paymentInputToken == paymentToken`, `paymentInputAmount == paymentAmount`, and `amountOutMin == 0`.

## Chain A: `DecisionPaymentSettlement`

Source: `contracts/src/DecisionPaymentSettlement.sol`.

| Function/event | Implemented interface and behavior |
|---|---|
| `registerTransaction(Terms)` | Buyer-authorized registration. Stores the complete Terms and computed terms hash; a transaction ID can be registered once. |
| `lockPayment(bytes32 transactionId, bytes32 termsHash)` | Buyer-authorized lock; checks exact terms hash, undecided state, unlocked status, and `block.timestamp < expiresAt`. Emits `PaymentLocked(bytes32 indexed transactionId, bytes32 termsHash, address payer, uint256 amount)`, where amount is `paymentInputAmount`. |
| `getTransaction(bytes32 transactionId)` | Returns `(ProtocolTypes.Terms terms, bytes32 termsHash, ProtocolTypes.Decision decision, ProtocolTypes.PaymentStatus paymentStatus)`. Reverts for an unknown transaction. This is the Chain A reservation/state read; there is no `getPaymentReservation` function. |
| `getDecision(bytes32 transactionId)` | Returns `(Decision decision, bytes32 termsHash, uint256 sourceChainId, address sourceContract, bytes32 recordId, uint64 nonce, uint256 decisionBlockNumber)`. The transaction ID is the getter argument and is not repeated in the return tuple. |
| `onReport(bytes metadata, bytes report)` | Checks `msg.sender == trustedForwarder`, decodes `ProtocolTypes.CoordinationReport`, requires undecided + payment locked + unexpired, validates all report terms/flags, then atomically records COMMIT and pays. Any failure reverts the state update and transfer. |
| `abort(bytes32 transactionId)` | Permissionless at `block.timestamp >= expiresAt`, only while undecided. Records ABORT and refunds a locked payment atomically. |
| `DecisionRecorded(bytes32 indexed transactionId, bytes32 termsHash, Decision decision)` | Emitted for COMMIT and ABORT. Only `transactionId` is indexed. |

`DecisionPaymentSettlement` exposes `computeTermsHash(Terms)` and `computeAssetObligationId(Terms)` as pure functions. It does not expose a payment-obligation getter or payment-obligation ID in its decision tuple.

## Chain B: `AssetSettlement`

Source: `contracts/src/AssetSettlement.sol`.

| Function/event | Implemented interface and behavior |
|---|---|
| Constructor | `AssetSettlement(address trustedForwarder, uint256 paymentChainId, address paymentContract)`. Pins the Chain A domain and Forwarder. |
| `lockAsset(Terms, bytes32 expectedTermsHash)` | Seller-authorized lock. Recomputes the complete terms hash and transfers the asset into escrow. Emits `AssetLocked(bytes32 indexed transactionId, bytes32 termsHash, address seller, uint256 amount)`. |
| `getAssetReservation(bytes32 transactionId)` | Returns `(ProtocolTypes.Terms terms, bytes32 termsHash, ProtocolTypes.AssetStatus status, ProtocolTypes.Decision decision, bytes32 decisionRecordId, uint64 decisionNonce)`. For an unknown transaction it returns zero Terms/hash, `NONE`, `UNDECIDED`, zero record ID, and nonce 0. |
| `onReport(bytes metadata, bytes report)` | Checks the configured Forwarder, decodes `ProtocolTypes.DecisionRelayReport`, requires the asset status to be `LOCKED`, validates source/destination/terms/obligation/record/participants/token/amount/expiry, then transfers once and stores the decision record. Repeated reports are rejected after the status leaves `LOCKED`. |
| `computeAssetObligationId(Terms)` | Pure function returning the canonical asset obligation ID used by the Chain B receiver. |

Relevant events are `DecisionReceived(bytes32 indexed transactionId, bytes32 termsHash, Decision decision, bytes32 decisionRecordId)`, `AssetDelivered(bytes32 indexed transactionId, bytes32 termsHash, address recipient, uint256 amount)`, and `AssetReleased(bytes32 indexed transactionId, bytes32 termsHash, address recipient, uint256 amount)`.

## CRE read interfaces

`raisinFi/my-workflow/contract-codec.ts` decodes the generated Hardhat ABI module:

- Chain A reads `getTransaction(bytes32)` and takes Terms, terms hash, decision, and payment status from the returned tuple.
- Chain B reads `getAssetReservation(bytes32)` and takes Terms, terms hash, status, decision, record ID, and nonce from the returned tuple. It calls `computeAssetObligationId(Terms)` on Chain B for the obligation binding.
- Chain A reads `getDecision(bytes32)` at `LAST_FINALIZED_BLOCK_NUMBER` for relay. The transaction ID is bound from the read argument; the returned chain ID, contract, decision record ID, nonce, and decision block number are preserved.
- Lock and decision event ABIs/topics are selected from generated artifact ABIs. Their indexed flags and event signatures are checked by artifact compatibility tests.

## Report payloads

Both settlement contracts implement `IReceiver.onReport(bytes metadata, bytes report)` and compare the caller to their immutable configured Forwarder. The report tuple is encoded as one static tuple, equivalent to `abi.encode(reportStruct)`. Field order below is from `ProtocolTypes.sol`.

### Chain A `CoordinationReport`

```solidity
struct CoordinationReport {
    bytes32 transactionId;
    bytes32 termsHash;
    uint256 paymentChainId;
    address paymentContract;
    uint256 assetChainId;
    address assetSettlement;
    address buyer;
    address seller;
    address paymentInputToken;
    uint256 paymentInputAmount;
    address paymentToken;
    uint256 paymentAmount;
    address assetToken;
    uint256 assetAmount;
    uint256 expiresAt;
    bool paymentLocked;
    bool assetLocked;
}
```

The CRE report encoder is `raisinFi/my-workflow/report-encoding.ts::encodeCoordinationReport`. Chain A validates every field against registered terms and its local payment status; `assetLocked` is a CRE-attested cross-chain assertion. The workflow must derive it only after matching the Chain B reservation.

### Chain B `DecisionRelayReport`

```solidity
struct DecisionRelayReport {
    bytes32 transactionId;
    bytes32 termsHash;
    Decision decision;
    uint256 sourceChainId;
    address sourceContract;
    uint256 destinationChainId;
    address destinationContract;
    bytes32 assetObligationId;
    bytes32 decisionRecordId;
    uint64 decisionNonce;
    uint256 sourceDecisionBlockNumber;
    address buyer;
    address seller;
    address assetToken;
    uint256 assetAmount;
    uint256 expiresAt;
}
```

The CRE report encoder is `raisinFi/my-workflow/report-encoding.ts::encodeDecisionRelayReport`. The current contract uses decision nonce 1. `decisionRecordId` is `keccak256(abi.encode(DECISION_RECORD_TYPEHASH, sourceChainId, sourceContract, transactionId, termsHash, uint8(decision), decisionNonce))`. Chain B validates these fields and prevents a second asset transfer.

The report structs are internal Solidity library types and therefore are not exposed as tuple components in the contract ABI artifact. Compatibility is verified by sending the production CRE-encoded COMMIT and ABORT payloads through the compiled `onReport` implementations in the cross-network Hardhat tests.

## Generated ABI and compatibility checks

Run `npm run typecheck` or `npm test` in `contracts`. The pretest/typecheck steps compile Solidity and run `contracts/scripts/export-abis.mjs`, which writes the Hardhat-artifact-derived ABIs to the web and CRE source trees. Contract tests assert the CRE ABI module equals the compiled artifacts and pass actual getter return encodings through the CRE decoders. They also pass the production CRE report encoders into each receiver and check duplicate behavior.

The tests use local Hardhat Sepolia/Base networks and a signer standing in for the Forwarder. They do not demonstrate CRE DON execution or testnet settlement. Isolated demo receivers have since been deployed on Sepolia (`0x46474063C039f76111d0a393B8266E377dF7b8e8`) and Base Sepolia (`0x9DbFA23d09deb3A66a7261de9E7e708A1b9bBc1A`) with the respective tenant mock Forwarders; `my-workflow/config.json` records their addresses and deployment blocks. This makes local mock-Forwarder testing possible but does not demonstrate CRE DON execution. Do not use the mock Forwarder for DON production deployments.
